## 1. 무엇을 하는 프로그램인가

초등학교 담임교사가 나이스(NEIS) 학교생활기록부에 넣을 문장을 만들고,
검토하고, 나이스로 옮기는 것을 돕습니다.

다루는 항목은 **학기당 최대 14가지**입니다.

| 묶음 | 항목 | 글자 상한 |
|---|---|---|
| 행동특성 | 행동특성 및 종합의견 | 400자 |
| 학기말 | 과목별 종합의견 (과목 수만큼) | 380자 |
| 창의적 체험활동 | 자율 · 동아리 · 진로 · 봉사 | 250자 |

## 2. 접속과 저장

### 접속
학교이름 · 학년 · 반 · 연도 **네 가지만** 입력합니다.
아이디도 비밀번호도 없습니다. 이 네 가지를 해시한 값이 학급 키입니다.

```
sessKey = hashKey(연도|학교명|학년|반)
```

### 저장은 두 겹

| 어디 | 무엇 | 언제 |
|---|---|---|
| `localStorage` (`neisgen_v1:`) | 이 브라우저의 작업 내용 | 입력 후 1~2초 |
| 계정 저장소 `data/users/<UID>/<key>` | 기기 간 이어쓰기 | 같은 타이밍에 미러 |

**`data/users/<UID>/` 는 교사 본인만 읽습니다.** 아티팩트 제작자도 못 봅니다.
→ NFR-1. 센서 01이 지킵니다.

예외는 **학년 공동 평가** 하나뿐입니다. 학년부장이 배포를 누른 평가 내역만
공유 경로 `gradeEvals/<연도|학교|학년|학기 해시>`에 올라갑니다.

### 충돌
다른 창이나 기기에서 더 최근에 저장하면 화면 아래 주황색 띠가 뜹니다
(`watchRemote` → `showConflict`). 자동으로 덮어쓰지 않습니다.

### 되돌릴 수 없는 작업
삭제 · 전체 생성 다시 돌리기 · 맞춤법 점검 — 이 셋 전에 내려받기를 권합니다. → NFR-7

## 3. 상태 구조

```js
S = {
  key, meta:{school, grade, cls, year}, count, subjects:[],
  behavTax, termTax, ccaCat,      // 교사가 고치고 추가할 수 있는 갈래 목록
  evals:{1:[], 2:[]},             // 평가 내역 (학기별)
  students:[ ... ],               // 번호만. 이름은 저장하지 않는다
  lead,                           // 학년부장 여부
  recv:{1:{}, 2:{}},              // 공동 평가 수신 시각
  spellLog:[], demo, setupDone, _ts
}
```

학기 한 칸은 이렇게 생겼습니다.

```js
blankSemester() = {
  behavior:{}, term:{}, extra:"",
  cca:{auto:[], club:[], career:[], service:[]},
  split:{auto:{}, club:{}, career:{}},     // 누가기록용 문장 쪼개기
  out:{behavior:"", term:{}, auto:"", club:"", career:"", service:""}
}
```

**학생 이름은 어디에도 없습니다.** 번호만 씁니다. → NFR-1

2학기는 1학기에 고른 학생 특성을 물려받고(`inheritSem2`), 교사가 고칠 수 있습니다.
평가 내역과 창체 선택은 학기별로 따로입니다.

### db 스냅샷은 반드시 복사해 쓴다
계정 저장소가 돌려주는 스냅샷 객체는 **동결되어 있습니다.** 그대로 상태로 쓰면
`Cannot add property 0, object is not extensible`로 조용히 실패합니다.
`clone()`을 거치고 `ensureShape()`로 모양을 맞춥니다.
→ 실제로 "창체 설정에서 클릭이 안 된다"로 나타났던 버그입니다.

## 5. 문장 생성

`buildPrompt()`가 프롬프트를 만들고 `generateOne()` / `generateAll()`이 돌립니다.
문장 생성은 아티팩트의 `sample` 기능을 씁니다.

### 링크로 들어온 사람은 문장 생성을 못 씁니다
`sample`은 아티팩트 소유자에게만 열립니다. `capInit()`이 그것을 확인해
`capState`를 `ready` / `nosample` / `muted`로 정하고, `nosample`이면 생성 단추를
잠그고 안내 띠를 띄웁니다.

> `capReady = true`를 `await` 앞에 두었다가 경고창이 쌓이는 버그가 있었습니다.
> `capPromise`로 한 번만 돌게 묶어 고쳤습니다.

### 임원 문장 (형식 고정)
```
<직위>으로서 (<기간>) 동안 ~
```
학급회장 · 학급부회장 · 전교학생회장 · 전교학생부회장은 **기간 입력이 필수**입니다.
따옴표를 붙이지 않습니다. `으로써`가 아니라 **`으로서`**입니다.

### 규칙 기반 대안 (시험판)
`src/sentence-assembler-pilot.html`은 **AI를 한 번도 부르지 않고** 문장을 만듭니다.
3갈래 × 10항목 × 4변형 = 120문장. → NFR-3, NFR-4

## 6. 나이스로 옮기는 세 가지 길

### 6-1. 순서대로 붙여넣기 (`openPasteRunner`)
한 번호씩 클립보드에 복사해 주고, 교사가 나이스에 Ctrl+V 합니다.

**프로그램은 나이스를 건드리지 않습니다.** → NFR-2. 센서 02가 지킵니다.

**탭 횟수는 끝까지 같습니다.** 문장이 없는 번호와 잠긴 칸도 같은 횟수로 지나갑니다.

| 항목 | Tab |
|---|---|
| 학기말 종합의견 | 3번 |
| 행동특성 및 종합의견 | 2번 |
| 창체 누가기록 | 2번 |

봉사활동은 입력 방식이 학교마다 달라 **이 기능을 만들지 않았습니다.**

카드에서 바로 고칠 수 있고(`runnerSet`), 고친 내용이 즉시 다시 복사됩니다.

### 6-2. 나이스 엑셀 채우기 (`openFillXlsx`)
나이스에서 내려받은 파일을 올리면 번호를 맞춰 문장 열만 채워 돌려줍니다.
**나머지 열과 서식은 원본 그대로**입니다. 파일은 브라우저 안에서만 열립니다.

### 6-3. 창체 엑셀 내려받기 (`openCcaExcel` → `buildNeisXlsx`)
나이스 내려받기 파일과 **같은 모양**으로 새로 만듭니다.

```
시트 이름 : "자율활동관리 특기사항 "     ← 끝 공백까지 그대로
머리글    : 영역 구분 / 학년도 / 학년 / 반 / 번호 / 학생개인번호 / 성명 / 특기사항
학생개인번호·성명 : 비움
특기사항  : 자율 + 빈 줄 + 진로 + 빈 줄 + (동아리명)동아리
봉사      : 넣지 않음
```
열 너비와 줄바꿈 서식까지 맞춥니다(`XL_WIDTH`, 스타일 0~3).

## 7. 그 밖의 기능

| 기능 | 함수 | 메모 |
|---|---|---|
| 맞춤법·띄어쓰기 점검 | `openSpell` / `runSpell` | 글자 단위 LCS 차이로 무엇이 바뀌었는지 보여 줌. `revertSpell`로 되돌림 |
| 학년 공동 평가 | `gradeEvalsPublish` / `gradeReceive` | 학년부장만 과목별 일괄 배포 |
| 평가 내역 파일 주고받기 | `exportEvalFile` / `openEvalImport` | 저장소를 공유하지 않고 파일로 주고받음 |
| 표 내려받기 | `doExcel` / `doHwpx` / `doHtml` | xlsx · hwpx · 한글용 html |
| 예시 학급 | `buildDemo` / `enterDemo` | 4학년 24명. **계정에 저장하지 않음** |

### 겹치지 않게 배정하는 방법
```js
dseq(arr, i, k) = arr[ floor(i / arr.length**k) % arr.length ]
```
자릿수 분해라서 한 학급 안에서 조합이 겹치지 않습니다.

> 처음에는 배수를 곱해 쓰다가 서로 mod 3으로 묶이는 바람에
> 국어 24명 중 5개만 서로 달랐습니다. → NFR-4, 센서 05

## 8. 아직 풀리지 않은 것

1. **배포와 기능이 맞바꾸기 관계입니다.**
   - 사본을 각자 만들면 → 문장 생성 ○, 계정 저장 ○, 공동 평가 ✗
   - 링크를 공유하면 → 공동 평가 ○, 문장 생성 ✗
   현재는 **평가 내역 파일 주고받기**로 우회하고 있습니다.

2. **문장 자산이 모자랍니다.** 규칙 기반으로 완전히 넘어가려면
   1,000~1,500문장이 필요한데 지금 시험판은 120문장입니다.

3. **사람 이름을 걸러낼 방법이 없습니다.** 성씨로 찾으면
   `나누어` `함께` `하는`까지 잡혀 오탐이 너무 많습니다. 현재는 포기했고,
   화면에 "못 잡는다"고 적어 두었습니다. → NFR-8

4. **어미 자동 변환은 여전히 불가능합니다.** ㅂ/ㄷ/ㅅ/르 불규칙 때문입니다.
